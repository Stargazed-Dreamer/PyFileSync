# PyFileSync

基于 PySide6 的跨平台文件备份工具，支持本地目录同步、移动硬盘备份与 Android 手机文件双向备份（通过 ADB）。提供增量更新、完全同步、断点续传、预览审核等能力，面向需要可靠文件备份的桌面用户。

## 特性

| 类别 | 功能 | 说明 |
|------|------|------|
| **手机备份** | ADB 双向备份 | 通过 `adb://` URI 直接备份手机文件到电脑，或从电脑推回手机（pull/push 自动识别方向）|
| | ADB 设备浏览器 | 图形化目录树浏览 Android 文件系统，懒加载 + 路径记忆 + 多设备切换 |
| | ADB 优雅降级 | 未安装 adb 时本地功能不受影响，手机相关按钮自动禁用并提示 |
| **可靠性** | 断点续传 | 支持暂停/继续；关闭窗口时自动保存进度；下次启动检测进度文件询问是否恢复 |
| | 错误隔离 | 单个文件失败不影响整体备份，失败清单在日志和界面中汇总 |
| | 持久化日志 | 自动轮转（>1MB 截断）、线程安全、会话标记、失败操作清单 |
| | 配置自动备份 | 写入前备份为 `<file>_old`，防止误改 |
| **备份策略** | 增量更新 / 完全同步 | 每条路径规则独立选择；完全同步会删除目标侧多余文件 |
| | 重复文件策略 | 覆盖 / 跳过 / 检查日期和大小（含 10 秒容差，兼容 FAT32/网络盘 mtime 精度）|
| | 时间戳增量备份 | 配置文件首行 `*时间戳`，跳过早于该时间的源文件，备份后自动更新时间戳 |
| **预览** | 操作清单预览 | 执行前预览将执行的 copy/delete 操作，区分新建/覆盖/删除 |
| | 容忍度合并算法 | 海量文件不刷屏，按目录深度指数级增长容忍度，合并显示为摘要行 |
| | 后台线程 | 预览在后台线程执行，不阻塞 UI |
| **性能** | RoboCopy 加速 | Windows 上启用 RoboCopy 批处理 + `/MT:N` 多线程；不可用时自动回退 Python |
| | 自适应并发复制 | 文件数 <8 单线程；小文件占比高时自动多线程；ADB 路径强制单线程 |
| | ADB 批量扫描 | `find -exec stat` 批量获取元数据（约 300 文件/秒），避免逐文件调用 |
| **易用性** | 人类可读配置 | `→` 分隔路径对、`❌`/`✔` 标记过滤、`|` 分隔元数据，纯文本可手编 |
| | 拖放支持 | 源路径、目标路径、排除、包含四个输入框全部支持拖放文件/文件夹 |
| | 路径智能显示 | 长路径自动截断为"前缀...最后一段"，DPI 适配，双击查看完整路径并可复制 |
| | 文件过滤 | 排除规则 + 包含例外（优先级更高），支持相对路径和绝对路径 |

## 安装

### 环境要求

- Python 3.8+
- PySide6
- ADB（可选，仅手机备份功能需要）

### 步骤

```bash
# 1. 克隆仓库
git clone https://github.com/Stargazed-Dreamer/filesync.git
cd filesync

# 2. 安装依赖
pip install PySide6

# 3. （可选）安装 ADB
#    Windows: 下载 Android SDK Platform Tools，解压后将其目录加入 PATH
#    macOS:   brew install android-platform-tools
#    Linux:   sudo apt install adb  (或对应发行版的包管理器)

# 4. 运行
python main.py
```

## 快速开始

1. 运行 `python main.py` 启动应用，建议最大化
2. 在"路径管理"标签页，填写源目录和目标目录，建议通过拖放目录来指定
3. 选择重复文件策略（覆盖/跳过/检查日期和大小）和增删策略（增量更新/完全同步）
4. （可选）填写排除/包含例外规则
5. 点击【保存到内存】保存规则，全部编辑完成后点击保存到文件，持久化配置
6. 点击"预览"查看将执行的操作（此时会开始扫描，可能需要一段时间）
7. 确认无误后点击"开始备份"

也可以直接编辑配置文件（见下节），程序启动时会加载。

## 配置文件说明

程序启动时会读取 `main_config.txt`（本地备份）和 `phone_config.txt`（手机备份）。仓库提供了示例模板：

- [main_config.example.txt](main_config.example.txt) — 本地备份配置示例
- [phone_config.example.txt](phone_config.example.txt) — 手机备份配置示例

复制为对应的 `*.txt` 后编辑即可。配置文件格式：

```
*2025.01.01 00:00:00                          # 顶行时间戳（用于"跳过早于时间戳"）

C:/Users/your_name/Documents -> D:/Backup/Documents |重复文件:检查日期和大小 |增删文件处理:增量更新
  ❌ tmp                                       # 排除 tmp 目录
  ❌ cache
    ✔ keep_this.log                            # 包含例外（即使父目录被排除也保留此文件）

C:/Users/your_name/Pictures → D:/Backup/Pictures |增删文件处理:完全同步   # → 与 -> 等价
```

**元数据项**（`|` 分隔，顺序不限）：
- `重复文件:覆盖|跳过|检查日期和大小`（默认覆盖）
- `增删文件处理:增量更新|完全同步`（默认增量更新）
- `状态:启用|禁用`（默认启用）

**过滤规则**（空格缩进）：
- `❌` 排除（支持相对路径和绝对路径）
- `✔` 包含例外（优先级高于排除，可做"排除整个目录但保留某文件"）

> 注：建议使用GUI编辑配置文件，而不是人工编辑

## ADB 手机备份

### 准备工作

1. 安装 ADB（见安装步骤）
2. 手机开启 USB 调试（设置 → 开发者选项 → USB 调试）
3. USB 连接手机和电脑
4. 手机上授权此电脑（首次连接会弹窗，点击"允许")
5. 命令行运行 `adb devices`，确认设备状态为 `device`（而非 `unauthorized` 或 `offline`）

### 配置手机备份

编辑 `phone_config.txt`，使用 `adb://<设备序列号>/<手机路径>` 格式：

```
# 手机相册备份到电脑（手机→电脑）
adb://SERIAL123456789/sdcard/DCIM -> D:/Backup/Phone/DCIM |重复文件:检查日期和大小

# 电脑铃声推送到手机（电脑→手机）
D:/Backup/Phone/Ringtones -> adb://SERIAL123456789/sdcard/Ringtones |重复文件:覆盖
```

设备序列号通过 `adb devices` 获取，或在应用内点击"浏览手机"按钮图形化选择。

### 设备浏览器

点击"浏览手机"按钮打开 ADB 设备浏览器：
- 多设备时下拉切换
- 目录树懒加载（展开时才加载子目录，避免卡顿）
- 路径记忆（按设备分别记忆，下次自动展开到上次位置）
- 选中目录后自动填入路径输入框

## 备份策略说明

### 增量更新 vs 完全同步

- **增量更新**：只复制源侧新增或修改的文件，不删除目标侧任何文件。适合"只增不减"的备份场景
- **完全同步**：在增量更新基础上，额外删除目标侧存在但源侧已不存在的文件，使目标成为源的镜像。适合需要精确镜像的场景（注意：会删除目标侧文件！）

### 重复文件策略

- **覆盖**：目标已存在则直接覆盖（不检查内容）
- **跳过**：目标已存在则跳过
- **检查日期和大小**（推荐）：比较 mtime 和 size，相同则跳过。含 10 秒容差，兼容 FAT32（2 秒精度）和网络盘的 mtime 精度差异

### 时间戳增量备份

配置文件首行 `*YYYY.MM.DD HH:MM:SS`。勾选"跳过早于时间戳"后，源文件 mtime 早于该时间戳则跳过。备份成功后时间戳自动更新为当前时间，形成闭环——下次只备份"上次备份之后修改过的文件"。

### 断点续传

- **暂停/继续**：点击暂停按钮在当前文件完成后暂停，进度保存；点击继续从断点续跑
- **关闭恢复**：关闭窗口时若备份进行中，自动等待当前文件完成并保存进度
- **启动恢复**：下次启动检测到进度文件时弹窗询问是否恢复上次未完成的备份

## FAQ

**Q: RoboCopy 不可用会怎样？**
A: 自动回退到纯 Python 复制器，功能完整但海量小文件场景性能略低。UI 上的 RoboCopy 复选框在非 Windows 系统会自动禁用。

**Q: ADB 设备显示 unauthorized 怎么办？**
A: 手机上会弹出"允许 USB 调试"的对话框，点击"允许"（建议勾选"始终允许"）。如果未弹窗，拔插 USB 或运行 `adb kill-server && adb start-server` 后重试。

**Q: 中文文件名备份失败？**
A: 程序已统一使用 UTF-8 编码处理文件名，正常情况不会失败。如遇 ADB 场景下的特殊字符问题（如方括号 `[` `]`），程序会自动中转临时路径再移动，无需手动处理。

**Q: 支持 macOS / Linux 吗？**
A: 支持。ADB 备份在三平台行为一致；RoboCopy 仅 Windows 启用，其他平台使用 Python 复制器。需自行安装 PySide6 和 adb。

**Q: 配置文件改错了怎么办？**
A: 每次写入配置文件前会自动备份为 `<file>_old`，可从 `_old` 文件恢复。
